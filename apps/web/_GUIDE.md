# apps/web — 웹 서비스 (Next.js App Router)

대시보드형 제품이다. **여신 진단은 이 제품의 기능 하나**이지 제품 전체가 아니다.
새 기능을 붙일 때 리포트 화면을 늘리지 말고 라우트를 하나 더 만든다.

## 라우트 지도

세 영역으로 나뉜다. **공개 포털**(로그인 전), **농가용**, **금융기관용**.
뒤의 둘은 같은 엔진을 서로 다른 관점으로 낸다.

## 금지사항

- **`limits.recommended` 를 "감당 가능한 금액" 이라고 부르지 않는다.** 셋의 뜻이 다르다.
  `available`=제도 한도, `recommended`=DSCR 1.25(소득이 **안 흔들린다는 가정**),
  `risk_based`=위기확률 기준(변동을 넣고 시뮬레이션). 대표 금액은 항상 `risk_based` 다.
  대시보드가 이걸 헷갈려 위기확률 64.9% 짜리 금액을 '감당 가능' 으로 띄운 적이 있다 —
  `lib/diagnosis.ts` 의 `headlineLimit()` 만 쓰고 직접 필드를 꺼내지 않는다.
- **`useEffect` 는 반드시 블록 본문으로 쓴다.** `useEffect(() => expr, [x])` 는
  **식의 반환값이 그대로 cleanup 으로 넘어간다.**
  사고 이력: `useEffect(() => el?.scrollIntoView(…), [turns])` 가 유저 환경에서만
  `useEffect must not return anything besides a function` 을 냈다. 우리 코드는
  undefined 를 반환하지만 브라우저 확장이 그 메서드를 패치하면 값이 생긴다.
  내 환경에서는 재현이 안 돼 원인을 찾는 데 오래 걸렸다.
  `apps/web/tests/effects.test.ts` 가 간결 본문을 막는다.
- **화면에서 숫자를 계산하지 않는다.** 합계·비율·한도는 전부 API 응답을 그대로 쓴다.
  프런트에서 한 번이라도 계산하면 리포트와 대시보드의 숫자가 갈라지고, 어느 쪽이
  맞는지 아무도 모르게 된다.
- **빈 메뉴를 만들지 않는다.** `lib/nav.ts` 에 올리는 항목은 반드시 실제 데이터가
  있어야 한다. 목업에 있던 '기상 위험'·'보험'을 뺀 이유가 이것이다
  (기상 관측 자료 없음, 보험료율 미공개).
- **세션을 `useEffect(…, [])` 로 한 번만 읽지 않는다.** `lib/useSession.ts` 를 쓴다.
  사고 이력: 2026-08-26 로그인 후 메인으로 가면 상단이 다시 '로그인' 으로 보였다.
  `UtilBar` 가 루트 레이아웃에 있어 클라이언트 이동으로는 remount 되지 않는데,
  `signIn()` 이 localStorage 만 바꾸고 떠 있는 구독자에게 알리지 않았다.
- **접근 통제는 `ready === true` 인 뒤에만 판단한다.** 서버 렌더와 하이드레이션 첫
  프레임에서는 세션이 항상 `null` 이다(서버가 localStorage 를 못 읽으니까).
  사고 이력: 위 버그를 고치면서 `ready` 가드를 빼먹었더니 **로그인돼 있어도
  로그인 화면으로 튕겼다.** 고치다 낸 사고라 같이 적는다.
- **역할은 계정이 정한다. 화면에서 고르게 두지 않는다.** 로그인 폼의 라디오 버튼으로
  역할을 고르던 시절엔 농가 계정으로 심사 화면에 들어갈 수 있었다.
  농가 `000000`, 금융기관 `222222` — `lib/auth.ts` 의 `ACCOUNTS` 가 유일한 출처다.
- **심사 화면에서 예시 데이터를 쓸 땐 무엇이 예시인지 화면에 쓴다.** `lib/applicants.ts`
  는 신원(이름·지역·접수번호)만 예시고 **금액·확률·판정은 전부 엔진이 실제로 계산**한다.
  가짜 심사 결과를 지어내면 화면 전체가 거짓이 된다.
- **개인정보를 서버로 보내지 않는다.** 진단 입력은 문서번호(URL)에 인코딩돼 있고
  농가 기본값은 localStorage 에 있다. `lib/auth.ts` 의 로그인은 **데모용이며 실제
  인증이 아니다** — 아이디·비밀번호가 코드에 박혀 있고 검증도 브라우저에서 한다.
  이 상태로 배포하면 안 된다.
- **공지·소식에 지어낸 정부 발표를 싣지 않는다.** `lib/content.ts` 의 공지는
  이 저장소에서 실제로 일어난 변경이고, 자료실은 실제 수집한 원문이다.
  화면을 채우려고 가짜 보도자료를 만들지 않는다.
- 리포트(`.sheet`)와 대시보드는 **색계가 다르다**. 리포트는 종이, 대시보드는 앱이다.
  한쪽 컴포넌트를 다른 쪽에 그대로 쓰면 대비가 깨진다 (실제로 깨진 적 있다).

## 화법 — 확정 2026-08-27

시안(현재/A/B)을 나란히 놓고 유저가 대목별로 고른 결과에서 역으로 뽑은 규칙이다.
원칙을 먼저 세우면 화면마다 다시 논쟁이 붙어서, **표본을 먼저 고르고 규칙을 뽑았다.**

1. **숫자와 조건은 공식적으로, 제시는 부드럽게.** 금액·확률·근거 문장은 그대로 두고
   권유와 안내만 해요체로.
2. **판정하지 않는다.** "감당할 수 있는" 처럼 우리가 결론 내린 표현 대신
   "확률 10% 기준" 처럼 조건을 밝힌다.
3. **읽는 법을 지시하지 않는다.** "…를 보시면 됩니다", "고려해주세요", "…을 뜻합니다"
   는 빼고 사실만 놓는다.
4. **쉬운 말이 앞, 용어는 뒤.** "은행이 보는 선(DSCR 기준)".
   **용어를 지우지는 않는다** — 농가가 은행에서 같은 말을 써야 한다.
5. **권유에는 숫자와 갈 곳을 붙인다.** "줄여 보세요" 가 아니라
   "2억으로 낮추면 6년차가 1,370만원 → [수익 전망]".
6. **화면마다 말투가 다르다.** 읽는 사람이 다르기 때문이다.

   | 영역 | 말투 | 이유 |
   |---|---|---|
   | 농가용 `app/app/**` · 공개 포털 | **해요체** | 처음 보는 사람에게 설명하는 자리 |
   | 리포트 `.sheet` | **합니다체** | 문서번호가 붙은 출력물, 은행에 들고 갈 종이 |
   | 금융기관 `app/bank/**` | **합니다체** | 심사역용 실무 화면. "감당 가능 금액" 같은 실무 용어도 그대로 |
   | 면책 · 법적 경계 | **합니다체** | "유권해석이 아닙니다" 는 경계 선언이지 사용자 판정이 아니다 |
   | 서비스의 입장 선언 | **합니다체** | "정부 발표를 옮겨 싣지 않습니다" 같은 것 |

   > 변환 도구는 `scripts/` 에 두지 않았다. 한국어 종결은 앞 글자 받침에 따라
   > `이에요`/`예요` 가 갈려서 기계 치환만으로는 문장이 깨진다. 안전한 어휘만 바꾸고
   > 나머지는 사람이 본다.
7. **한계를 먼저 밝힌다.** 보수적인 부분과 낙관적인 부분을 숫자 옆에 한 줄로.
   뒤에 숨기면 변명이 되고 앞에 두면 근거가 된다.
8. **결론을 먼저, 근거는 접는다.** 지우지 않는다 — 근거를 다 보여주는 것이 이 서비스가
   신뢰를 얻은 이유다. 첫 화면에는 결론 한 줄과 핵심 숫자만.
9. **예외 — 가장 심각한 한 가지는 부드럽게 하지 않는다.** 무차입 상태에서도 생활비를
   못 채우는 경우처럼 차입 조정으로 풀리지 않는 상태는 단정형으로 쓴다.
   위험을 낮춰 말하면 사람이 돈을 잃고 높여 말하면 기회를 잃는데, 회복 가능성이 다르다.

## 모양과 움직임

- **정부 포털의 신뢰감 + 토스의 읽기 편함.** 색계·정보 구조·표는 정부 쪽,
  여백·큰 숫자·부드러운 전환은 토스 쪽에서 가져온다. 둘 중 하나로 기울지 않는다.
- 반경은 `tailwind.config.ts` 토큰만 쓴다. 2px → 10~16px. **표는 각지게 둔다.**
- **한 화면에 강조는 한 곳.** 핵심 숫자 하나만 크게 두고 나머지는 회색조로 내린다.
  전부 강조하면 아무것도 강조되지 않는다.
- **움직임은 상태 변화를 설명하는 것만.** hover·focus·active·값 갱신까지다.
  스크롤 연동이나 장식용 애니메이션은 넣지 않는다.
- `prefers-reduced-motion: reduce` 를 반드시 존중한다 (`globals.css` 에 전역 처리됨).
- 리포트(`.sheet`)는 인쇄물이다 — 반경도 전이도 넣지 않는다.

## 접근성 — 정부 포털을 표방하면 지켜야 한다

> 글자크기 조절(±) 버튼은 뺐다 — 브라우저 확대가 같은 일을 더 잘 하고, 좁은 화면에서
> 자리만 차지했다. 접근성은 대비·최소 글씨·터치 대상으로 지킨다.

`python scripts/ui_check.py http://localhost:3000` 으로 잰다. 커밋 훅에는 안 걸려 있다
(서버가 떠 있어야 해서). **화면을 만들거나 색을 바꿨으면 직접 돌린다.**

사고 이력: 2026-08-26 이 도구를 처음 돌렸더니 홈 75건, 리포트 110건이 나왔다.
`gov-ink3` 가 3.84:1, `paper-ink3` 가 3.06:1 로 AA(4.5:1) 미달이었고, 11px 본문이
44곳, 터치 대상 미달이 37곳이었다. 정부 포털 톤을 표방하면서 접근성이 깨져 있었다.

- **색은 눈으로 고르지 않는다.** 팔레트를 바꿀 땐 대비율을 계산하고 주석에 남긴다
  (`tailwind.config.ts` 참조). 전경색은 **그 색이 놓일 가장 어두운 배경** 기준으로 고른다 —
  `paper-ink3` 는 `paper-bg` 가 아니라 `paper-soft` 에서 4.5:1 을 넘어야 한다.
- **본문 최소 12px.** 차트 축 라벨(Recharts `fontSize`)도 포함이다.
- **조작 대상은 44×44.** 필터 칩·탭·입력은 `min-h-11`. 본문 속 인라인 링크는 예외
  (WCAG 2.5.8 inline 예외).

### 인정한 예외 (도구가 계속 잡지만 고치지 않는다)

| 항목 | 이유 |
|---|---|
| `a.sr-only 1×1` — 본문 바로가기 | 포커스 전엔 숨는 것이 설계다. 키보드 사용자에게만 보인다 |
| `input.sr-only 1×1` — 라디오 | 실제 조작 대상은 감싸는 `<label>` 이고 그건 44px 을 넘는다 |
