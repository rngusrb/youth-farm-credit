# 청년농 여신 설계 서비스 — 데스크톱 UI 개편 PRD

작성일: 2026-09-05 · 상태: 사용자 지정 5단계 반영 · 검토용 초안 · 기준 코드: ab4627c

## 1. 목적과 문제

청년농이 자신의 경영 상태와 자금 부족 시점을 이해하고, 조건을 바꿔 비교한 뒤 상담에 사용할 진단을 남기도록 한다. 기존에 구현된 계산 기능을 농가의 의사결정 순서로 연결하고, AI 농사 자금지도를 중심으로 진단·설명·개선안을 이어주는 UI 개편이다.

현재 메뉴는 농장 정보 → 건강검진 → 자금지도 → 상담사 → 맞춤 처방의 5단계를 제공한다. 개편에서는 이 순서를 유지하면서 첫 화면의 핵심 결과, 현재 입력 조건, 다음 행동을 명확하게 만든다. 사용자 혼란이나 이탈률은 아직 측정하지 않았으며, 문제의 크기는 사용성 검증으로 확인한다.

### 사용자 지정 핵심 5단계

아래 명칭과 설명을 내비게이션·페이지 제목·유저 플로우의 기준으로 사용한다. 2단계는 경영/금융 진단의 요약, 3단계는 시각화 분석, 4단계는 진단 결과와 원인의 상세 설명 및 대화, 5단계는 실행 가능한 개선안으로 역할을 나눈다.

| 순서 | 화면명 | 사용자에게 제시할 설명 | 핵심 산출물 |
|---|---|---|---|
| 1 | 내 농장정보 입력 | 농장·경영·자금정보 간편 입력 | 현재 농장 정보와 올해 농사 및 자금계획 |
| 2 | AI 농가 건강검진 | 유사 농가 대비 내 농장 상태 비교 | 경영·금융 진단 요약과 비교 근거 |
| 3 | **AI 농사 자금지도** | **1년 자금흐름과 미래 위험시점 시각화** | 월별 자금흐름, 부족 시점, 장기 상환 위험 지도 |
| 4 | AI 농가 상담사 | 진단 결과 기반 자유로운 질문·시뮬레이션 상담 | AI가 생성한 진단 결과·원인 상세 설명과 조건별 비교 |
| 5 | AI 맞춤 처방 | 금융·정책 추천, 신청서 작성, 작목전환 제안 | 맞춤형 개선방안·금융 솔루션·정책 제안, 신청서 초안, 작목 전환 상담 |

### 단계별 경험 설계

**1. 내 농장정보 입력:** 한 단계 안에서 ‘현재 농장·경영 현황 → 올해 농사 및 자금계획 → 입력 확인’ 순서로 구성한다. 현재 면적과 올해 계획 면적, 현재 소득 실적과 계획에 따른 추정값을 구분한다. 기존 지원 필드는 작목·면적·생활비·기타 원리금·소득 실적·상품·계획 면적·목표 차입금이며, 계산에 사용하지 않는 필드는 추가하지 않는다.

**2. AI 농가 건강검진:** 농가의 경영 상태와 금융 상태를 요약하고 유사 농가 비교를 제공한다. 다만 현재 확인된 기능은 통계 평균 기반 비교이므로 ‘유사 농가’의 작목·규모·지역·기준연도와 표본이 확보된 범위만 비교한다. 비교집단을 만들 수 없는 경우 ‘해당 작목 통계 평균 대비’로 정확하게 표시하고 지역·규모까지 일치하는 농가인 것처럼 표현하지 않는다. 새로운 유사 농가 집단 구성은 데이터 가용성 확인이 필요한 확장 요구사항이다.

**3. AI 농사 자금지도 — 핵심 기능:** 화면의 가장 큰 영역을 1년 월별 자금흐름에 배정한다. 월별 수입·지출·잔액 중 실제 API가 제공하는 값을 표시하고 부족 시점을 강조한다. 월을 선택하면 해당 월의 구성과 원인을 확인하며 ‘이 시점이 왜 위험한가요?’로 상담에 연결한다. 미래 위험은 별도 장기 보기에서 거치 종료·원리금 부담 증가 시점을 표시한다. 월별 위험과 연차별 위험을 같은 축에 섞지 않는다. 차트와 함께 금액·단위가 명확한 표를 제공한다.

**4. AI 농가 상담사:** 진입 시 기존 진단 결과를 바탕으로 ‘진단 요약 → 주요 원인 → 영향을 주는 조건’을 먼저 설명하고 자유 질문을 이어간다. 질문을 먼저 입력해야만 결과 설명을 볼 수 있는 구조를 피한다. 자금지도에서 선택한 월·연차·시나리오를 함께 전달해 문맥을 유지한다. AI는 엔진 결과와 근거를 설명하며, 원인 추정은 확정 원인과 구분한다. 차입금·면적·생활비 등을 바꾼 시뮬레이션은 현재 조건과 비교해 보여준다.

**5. AI 맞춤 처방:** 진단에서 발견한 문제와 각 개선방안을 연결하고 예상 효과·적용 조건·제도 근거를 함께 보여준다. 금융·정책 추천은 근거가 있는 후보와 검토 의견으로 제공하며, 신청 자격 충족이나 승인 결과로 표현하지 않는다. 하위 작업은 ‘신청서 초안 작성’과 ‘작목 전환 상담’으로 명확히 나눈다. 초안은 입력 정보와 확인된 진단을 채우고 모르는 항목은 확인 필요로 남겨 사용자가 검토·수정한다. 작목 전환은 후보 선택 → 현재 작목과 소득·변동성 비교 → 전환 비용·재배 역량 등 미반영 조건 확인 → 추가 상담 또는 계획 수정으로 이어진다.

## 6. 정보·수치 규칙

1. 대표 금액은 `risk_based`의 권장 차입이다. `available`은 제도상 신청 가능 한도, `recommended`는 은행이 보는 선(DSCR 기준)으로 구분한다.
2. 금액·확률은 엔진 출력만 사용한다. UI와 LLM이 임의 점수·확률·한도를 생성하지 않는다.
3. 소득 실적이 있으면 모든 관련 화면이 같은 실적과 면적·계획 조건을 전달한다. 조건 변경 후 이전 결과는 갱신 필요 상태로 표시한다.
4. 권장 차입 0원과 API 오류·데이터 없음은 별개다. 무차입 상태의 생계 부족은 원인을 명시하고 생활비·소득·규모 검토로 연결한다.
5. 시나리오 변경은 저장된 원본 농장 정보를 자동으로 덮어쓰지 않는다. 적용 확인과 결과 재계산이 필요하다.
6. 출처·기준 시점·가정은 결과 가까이에 요약하고 상세 근거를 펼칠 수 있게 한다.
7. 농가 안내는 쉬운 해요체, 리포트와 금융기관은 합니다체를 사용한다. 자격·대출 승인이나 결과를 보장하는 표현은 쓰지 않는다.

## 7. 상태와 데이터 경계

현재 농장 정보와 리포트 목록은 브라우저 localStorage에 저장된다. 기기 간 동기화와 실제 인증은 이번 UI 개편에서 추가하지 않는다. 계산 요청에는 필요한 농장 조건이 API로 전달된다.

|---|---|
| 첫 방문·정보 없음 | 입력 안내, 샘플값과 내 정보를 구분 |
| 계산 중 | 로딩과 진행 설명, 중복 실행 방지 |
| 서버 연결 실패 | 입력 유지, 재시도 제공, 정상 결과처럼 표시하지 않음 |
| 일부 분석 실패 | 성공 영역 유지, 실패 영역에서 별도 재시도 |
| 소득 실적 없음 | 통계 추정 경로와 출처 표시 |
| 검색 근거 없음 | 확인할 근거를 찾지 못했다고 표시, 질문 수정 가능 |
| 저장 실패 | 저장 완료 표시 금지, 재시도·결과 열람 가능 |
| 조건 변경 | 기존 결과에 갱신 필요 표시, 재계산 후 최신 표시 |

## 8. 검증과 성공 지표

아래는 출시 성과가 아니라 사전 사용성 검증 목표다.

- 청년농 또는 유사 사용자 5명 중 4명 이상이 도움 없이 정보 입력→자금지도까지 완료한다.
- 5명 중 4명 이상이 권장 차입과 제도 한도의 차이, 첫 부족 시점 또는 부족 없음 상태를 설명한다.
- 같은 조건의 주요 화면에서 소득 기준·금액 불일치 0건.
- 지도에서 선택한 위험시점이 상담의 설명과 후속 처방에 동일하게 반영된다.
- 신청서의 미확인 항목과 작목 전환의 미반영 비용이 확인 필요로 표시된다.
- 필수 화면의 빈 상태·오류·로딩·정상 상태를 각각 확인한다.
- 데스크톱과 375px 화면에서 핵심 동작 수행, 키보드 접근·대비·조작 크기 점검.
- 구현 시 `python scripts/harness.py all`, `python scripts/ui_check.py all --all-viewports` 수행.

운영 측정 제안: 정보 저장 성공률, 입력 시작→지도 확인 전환율, 상담 후 조건 비교율, 리포트 저장 성공률. 분석 수집은 현재 구현 여부 미확인이며 신규 도입 시 별도 범위를 정한다. 원시 소득값과 상담 문장을 분석 이벤트에 넣지 않는다.

## 9. 구현 전 확정할 항목

- UI Kit 원본 프레임의 상세 컴포넌트·토큰과 재사용 조건.

- 신청서 초안의 대상 서식과 편집·출력 방식.
- 이 문서의 레이아웃 제안값과 첫 화면 시안.
