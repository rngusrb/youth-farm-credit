### RISK-010: 「버틸 수 있는 선」 — 고정 시나리오 대신 경계를 찾는다

**상태**: done
**우선순위**: high
**관련 파일**: `apps/api/engine/` (신규), `apps/web/app/app/safety/`

지금 안전진단은 고정 시나리오 5개를 대입한다. 딸기 1,300평 기준 실측:

```
가격 하락    소득 -49.2%  못 버팀
생산량 감소  소득 -73.9%  못 버팀
복합 충격    소득 -108.3% 못 버팀
```

**거의 다 "못 버팀"** 이다. 남의 가정이라 이 농가에 얼마나 가까운 위험인지 알 수 없고,
농가에게는 "그래서 어쩌라고" 가 남는다.

거꾸로 찾는다 — **이 농가는 어디까지 버티나.**

> 도매가가 지금보다 **N%** 떨어지는 데까지는 버팁니다.
> 그 아래로는 6년차에 무너집니다.

**왜 이게 AI 처럼 보이나**: 시나리오를 대입하는 게 아니라 **경계를 탐색**한다.
이분법 탐색은 `levers.solve_for` 에 이미 있고(생활비·면적 축), 몬테카를로도 있다.
**가격 축을 하나 더 여는 일**이다. 숫자는 전부 엔진이 만들고 LLM 은 문장만 쓴다.

**완료 기준**
- 엔진 함수가 가격 충격의 경계값을 돌려준다 (crisis_prob 이 감내 기준을 넘는 지점)
- 경계가 없으면(어떤 하락에도 버팀 / 지금도 못 버팀) 그 사실을 그대로 밝힌다
- 결정론: 같은 입력에 같은 답. 시드 고정 검사 포함
- 화면이 경계값과 "그 아래로는 몇 년차" 를 함께 보여준다

**제약사항**
- `engine/` 이므로 프롬프트·환경변수·네트워크 금지 (폴더 금지사항)
- 외부 시세 API 에 **의존하지 않는다** — apis.data.go.kr 이 지금 504 이고
  캐시 파일도 아직 없다. 시세 연결은 있으면 좋은 한 줄이지 주인공이 아니다.

### UX-021: 하드코딩 시세 제거 — 되는 기능으로 만든다

**상태**: done
**우선순위**: high
**관련 파일**: `apps/web/components/AuctionSummary.tsx`

**무엇이 문제인가**
`AuctionSummary.tsx` 가 딸기 도매가를 코드에 박아 두고, 외부 API 가 실패하면
그 값으로 화면을 채운다 (58줄 초기값, 75~80줄 실패 시 재주입).
화면에는 "최근 자료" 배지와 "최근 조사일" 이 붙어 **실제 조회 결과처럼 보인다.**

**2026-09-07 확인 — 지금은 그 값이 틀렸다**
제공기관 API 가 복구됐고 실데이터가 온다. 비교하면:

```
실데이터 : 8440, 8380, 8310, 8170, 8100  → 최근 8,100원
하드코딩 : 8440, 8380, 8310, 8170, 5923  → 최근 5,923원
```

앞 4개는 같고 **마지막 하나만 다르다.** 한때 받아온 값을 붙여넣은 것으로 보이는데,
최신값이 실제와 어긋난다. 하드코딩이 지금은 **틀린 숫자를 보여주고 있다.**

**완료 기준**
- 하드코딩 제거 (두 곳 모두 — 75줄이 진짜 원인이라 58줄만 지우면 안 없어진다)
- 자료가 오면 실데이터를 보여준다
- 자료가 없으면 **왜 없는지** 밝힌다. "모으고 있어요"(우리가 미완성인 것처럼 읽힘) 대신
  제공기관 응답 없음을 말한다
- 마지막 확인값 폴백(`data/market_last_known.json`)이 실제로 채워지는지 확인 —
  지금까지 한 번도 생긴 적이 없다 (쓰기 조건이 `if items` 인데 items 가 늘 비었다)
- 검사: 코드에 가격 상수가 없어야 한다 (재발 방지)

**하지 않는 것**: 가격을 추정해 채우기. 근거가 없다.
