# SPRINT 2026-08-26 — 리포트 한 장 → 정부 포털형 양면 서비스

## 목표

착수 시점의 가설: **여신 진단은 제품이 아니라 제품의 기능 하나다.** 지금까지는
"입력 → 리포트 한 장" 이 전부였고, 그 리포트를 잘 만드는 방향으로만 갔다.
실제 서비스는 농가가 평소에 들어와 보는 곳이어야 하고, 같은 분석이 금융기관에는
다른 관점으로 필요하다.

부수 가설: 제도 근거(RAG)가 항상 "근거 없음"을 반환하는 것은 기능 미완이 아니라
**코퍼스 미투입**이다. 진짜 원문을 넣으면 그대로 동작할 것이다.

### S-001: 시행지침 코퍼스 투입 + 검색 품질 (`3d69482`)
- **완료 기준 달성**: ✅
- **한 일**: 명세 §6 대상 문서의 2026년 현행판 3종을 실제로 수집해 조항 단위로 색인.
  후계농업경영인 육성사업(HWPX) · 청년농업인 영농정착지원사업(HWPX) ·
  우수후계농업경영인 육성사업(PDF). 총 709개 조항.
- **핵심 결정**
  - **원문 txt 를 저장소에 커밋한다.** 수집 CLI(`rag/fetch_guidelines.py`)는 1회성이고,
    클론한 사람은 네트워크도 pdftotext 도 없이 `python -m rag.ingest` 만 하면 된다.
    `crops.json` 을 만드는 `stats/calibrate_*.py` 와 같은 패턴.
  - **확장어는 IDF 상위 2개만, 그리고 RRF 로 융합한다.** 처음엔 용어집 확장을
    질의에 덧붙였는데 개선이 **정확히 0** 이었다. 원인은 확장어 7개가 원 질의를
    희석시킨 것 — '연령' 하나만 붙이면 1위인데 7개를 붙이면 10위 밖으로 밀렸다.
    확장 질의를 따로 돌려 순위만 합치니 해결됐다.
- **결과**: recall@5 6/8 → **8/8**, 1위 정확도 5/8 → 7/8 (질문 8개, 손으로 만든 것)
- **재현 명령어**
  ```

  python -m pytest tests/test_rag_corpus.py -q
  ```

### S-003: 정부 포털형 양면 서비스 + 핵심기능 3개 (`34ff634`)
- **완료 기준 달성**: ✅

  - **월별 현금흐름**(`engine/cashflow.py`) — 총수입은 출하월에, 경영비·생활비는

  - **스트레스 테스트**(`engine/stress.py`) — 가격 20%↓ · 생산량 30%↓ ·
    금리 25bp↑ · 재해 빈발 · 복합.
  - 데모 로그인(`000000` / `111111`).
- **핵심 결정**

    영업레버리지를 계산할 수 없어 월별 현금흐름도 스트레스 테스트도 불가능했다.

  - **공지·자료실에 가짜 정부 발표를 싣지 않는다.** 공지는 이 저장소의 실제 변경
    이력, 자료실은 실제 수집한 원문, FAQ 는 누르면 그 자리에서 원문을 검색한다.
- **재현 명령어**
  ```

  python -m pytest tests/test_cashflow.py tests/test_stress.py -q

  ```
