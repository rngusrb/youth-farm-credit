# 청년농 여신 설계 서비스

청년 농업인이 정책자금을 신청하기 전에, 자신이 감당할 수 있는 차입 규모를 스스로
계산하고 상환 위험을 미리 확인하는 서비스.

- **하는 것** — 적정 차입 한도 산출, 상환 리스크 시뮬레이션, 제도 요건 근거 응답
- **하지 않는 것** — 부도 예측, 신용평가, 대출 알선, 상품 추천

## 설계 원칙

> **숫자는 LLM 이 생성하지 않는다.**
> 모든 금액·확률·비율은 `apps/api/engine/` 의 결정론적 코드가 계산한다. LLM 은
> (a) 자연어 → 구조화 입력, (b) 계산 결과 → 자연어 설명 두 가지만 담당하며,
> LLM 문장에 등장하는 수치는 엔진 출력과 대조해 **불일치 문장을 제거한 뒤** 반환한다.

API 키가 없으면 규칙기반 슬롯 추출과 템플릿 해설로 자동 전환되므로, 키 없이도
전체 플로우가 동작한다.

## 세 가지 한도

같은 농가에 대해 세 개의 숫자를 나란히 냅니다. 무엇을 기준으로 삼느냐의 문제이지
어느 하나가 정답은 아닙니다.

| 한도 | 기준 | 케이스 A 값 | 그 금액에서의 2년연속 위기확률 |
|---|---|---|---|
| 제도상 신청 가능 | 시행지침 한도 | 5억원 | 99.9% |
| DSCR 기준 권장 | 상환여력 ÷ 원리금 ≥ 1.25 | 3억 3,645만원 | 77.0% |
| **상환위험 기준** | 2년 연속 부족확률 ≤ 10% | **2억 563만원** | 10.0% |

### 한도 0원이 나오는 경우

차입을 0 으로 줄여도 소득이 생활비 아래로 떨어지면 상환은 밀립니다. 이때
`binding_constraint` 가 `"livelihood"` 가 되고, 화면은 "0원"을 계산 결과가 아니라
**진단**으로 설명합니다 — *"지금 문제는 얼마를 빌리느냐가 아니라 이 규모로 생계가
되느냐"*. 장미 900평이 이 경우로, 대출 없이도 2년 연속 적자 확률이 16.4% 입니다.
차입 축소로는 해결되지 않으므로 해설과 선택지도 규모·생활비 쪽으로 바뀝니다.

DSCR 한도는 **기대소득 하나로 계산하는 결정론적 값**이라 그 금액에서도 위험이
남습니다. 소득 분포까지 반영해 확률로 역산한 것이 상환위험 기준 한도입니다.
계산은 `engine/risk_limit.py` 의 이분탐색이며, 공통난수(common random numbers)를
써서 표본오차 없이 단조성이 보장됩니다.

## 소득 변동은 왜 생기나 — 요인분해

σ 는 "얼마나 흔들리나"만 말한다. 소득조사가 **농가수취가격과 주산물수량을 따로**
공표하므로, "**왜** 흔들리나"까지 쪼갤 수 있다 (`stats/factors.py`, 204개 작목-연도).

```
소득 = 총수입 − 경영비
Δlog소득 ≈ (총수입/소득)·(Δlog가격 + Δlog수량) − (경영비/소득)·Δlog경영비
```

| 작목 | 주원인 | 가격 | 수량 | 비용 | 탄력성 |
|---|---|---|---|---|---|
| 딸기(시설,수경) | 가격 | 126% | 2% | −28% | −0.28 |
| 토마토(시설,수경) | 가격 | 71% | 26% | 8% | −0.14 |
| 가지(시설) | 가격 | 95% | 5% | 1% | −0.16 |
| 시금치(시설) | **수량** | 46% | 60% | 1% | 0.02 |

합이 100%를 넘는 것은 영업레버리지 때문이다. 음수는 그 요인이 변동을 **완충**했다는
뜻이다(나쁜 해에 비용도 줄어드는 자연 헤지). 선형근사 오차는 잔차로 남겨 보고하며,
실측에서 94~107% 로 닫힌다.

**처방이 달라진다.** 가격 주도형이면 계약재배·출하 분산, 수량 주도형이면 재해보험·
시설 보강. 결과 화면이 작목별로 다른 대응을 제시한다.

**부수 효과 — 가정 하나가 또 사라졌다.** 가격-수량 탄력성을 −0.5 로 찍어 뒀었는데
17작목 실측 중앙값은 **−0.17** 이었다. 가정이 실제의 3배로 과대했고, 그만큼 가격
변동이 소득으로 전달되는 정도를 과소평가하고 있었다.

## σ 를 어떻게 알아낼 것인가

σ(소득 변동성)는 결과의 모든 확률을 지배하는데 실측이 어렵습니다. 세 갈래 경로를
모두 구현해 두었고, 서로 대체가 아니라 **역할이 다릅니다.**

| 경로 | 잡아내는 것 | 관측 수 | 재배방식 구분 | 환산 가정 | 상태 |
|---|---|---|---|---|---|
| KAMIS 일별 도매가격 | 시장 공통 충격 σ_공통 | 수천 | ✗ (품목 단위) | 필요 | 키만 있으면 동작 |
| KOSIS 농산물소득조사 | 소득 총변동 (전국 평균) | ~20 | **✓** | **불필요** | 키만 있으면 동작 |
| 농가 소득이력 입력 | 그 농가의 실제 변동 | 3~10 | ✓ | 불필요 | **지금 동작** |

### 1) KOSIS 농산물소득조사 — 실측 완료 ✅

```bash
export KOSIS_API_KEY='...'      # https://kosis.kr/openapi/ 활용신청
python -m stats.calibrate_kosis          # 전 작목
python -m stats.calibrate_kosis --dry-run
```

**실측 결과 (2013~2024, 전국평균 소득 시계열):**

| 작목 | 계열 | n | σ_공통 | 레버리지 이전 | 최종 σ |
|---|---|---|---|---|---|
| 딸기(시설,수경) | 시설딸기 | 12 | 0.110 | ×0.99 | 0.202 |
| 딸기(시설,토경) | 시설딸기 | 12 | 0.111 | — | 0.203 |
| 토마토(시설,수경) | 시설토마토(촉성) | 10 | 0.236 | **×1.33** | 0.291 |
| 가지(시설) | 시설가지 | 12 | 0.158 | — | 0.232 |
| 시금치(시설) | 시설시금치 | 12 | 0.267 | — | 0.317 |
| 장미(시설) | 시설장미 | 12 | 0.288 | — | 0.335 |

전 작목 0.20 동일 가정이었지만 **실제로는 딸기와 장미가 2.6배 차이**입니다.
딸기가 0.202 로 나온 것은 원래 가정이 우연히 맞았던 것이고, 토마토·시금치·장미는
크게 벗어나 있었습니다.

**실호출로 확인한 함정 세 가지** — 명세만 보고 짰으면 전부 조용히 틀렸을 것들입니다.

1. **`objL1`·`objL2` 를 둘 다 보내야 합니다.** 작목과 비목이 각각 별개의 분류축이라,
   하나만 보내면 `err 20 필수요청변수값이 누락되었습니다. (objL)`.
2. **표마다 두 축의 순서가 반대입니다.** 구표 `DT_143002_A003` 은 C1=작목/C2=비목,
   신표 `DT_143002_E003` 은 그 반대입니다. 축을 고정하면 작목과 비목이 서로 바뀝니다.
   `C1_OBJ_NM` 을 읽어 판정합니다.
3. **오류도 HTTP 200 으로 옵니다** (`{"err","errMsg"}`). 상태코드로 판단하면 안 됩니다.

또 `ITM_NM` 은 `금액/수량/비율` 하나뿐이라 쓸모가 없고, 실제 비목명(총수입·경영비·
소득)은 분류축에 들어 있습니다. `소득` 은 `소득률` 에도 부분일치하므로 비율 항목을
배제해야 합니다.

**한계 — 재배방식 구분은 2023년부터입니다.** `시설딸기(수경)`, `시설토마토(수경)` 은
2023~2024 두 해뿐이라 σ 를 잴 수 없습니다. 그래서 장기 σ 는 관행 계열에서 재고,
아래의 레버리지 비율로 수경 쪽에 옮깁니다.

**한계 — 공표값은 전국 평균입니다.** 농가별 특이 충격이 상쇄돼 있어 여기서 잰 σ 는
개별 농가 변동의 **하한**입니다. 그래서 통째로 교체하지 않고 공통 성분으로만 씁니다.

### 1-b) 계층 축소 — 11년 관측을 얼마나 믿을 것인가

작목별 σ 원추정치는 0.111~0.288 로 2.6배 벌어진다. 그런데 관측 11년으로 잰 σ 에는
표본오차가 크게 섞여 있다. 20작목의 σ 분포를 추정해 그 안에서 신호와 잡음을 갈랐다
(`stats/hierarchical.py`).

```
작목 차이 중 실제 신호     42%
표본오차                58%
```

그래서 각 작목의 σ 를 관측 수에 비례해 전체 분포 쪽으로 당긴다. 격차가 **2.6배에서
1.5배로** 좁아지는데, 그게 데이터가 실제로 지지하는 폭이다. 이 축소를 끄려면
`--no-pool` 을 준다.

**계열이 2년뿐인 수경 작목**은 이 구조에서 자연스럽게 처리된다 — 같은 품목의 관행
계열(이미 축소된 값)을 기준점으로 삼고 레버리지 비율만 곱한다. 농가 개인 이력에 쓴
축소추정과 **같은 아이디어를 한 층 위에서** 적용한 것이라, 전체가 3단 계층이 된다.

```
전체 작목 분포  →  이 작목의 σ  →  이 농가의 σ
```

### 1-c) KAMIS 도매가 교차검증 + 시장 국면

완전히 다른 자료(KAMIS 일별 도매가, 1,147~2,695 거래일)로 같은 값을 다시 쟀다
(`stats/garch.py`, `stats/calibrate_market.py`).

| 작목 | KAMIS 연평균가 σ | KOSIS 농가수취가 σ | 차이 |
|---|---|---|---|
| 딸기 | 0.091 | 0.083 | **0.008** |
| 토마토 | 0.195 | 0.100 | 0.095 |
| 시금치 | 0.237 | 0.104 | 0.133 |

딸기에서 두 기관의 독립 조사가 사실상 일치한다. 토마토·시금치의 차이는 도매시세와
농가수취가의 유통 단계 차이, 품종 구성 차이로 설명된다.

**중요 — 일별 σ 를 √250 배로 연율화하면 안 된다.** 농가는 시즌 내내 여러 가격에
팔아 사실상 연평균을 받는다. 순진하게 연율화하면 실측 대비 **3~10배 과대**해진다
(딸기 0.395 vs 0.091). `annual_average_series` 가 연평균으로 접은 뒤 σ 를 낸다.

GARCH(1,1) 로 변동성의 시간 구조도 쟀다. 딸기는 지속성 0.71(반감기 2일)로 충격이
금방 잦아들고, 토마토·시금치는 0.95~0.96(반감기 15~18일)으로 오래 간다.
**현재 국면은 한도에 반영하지 않는다** — 25년 상환에 본질적인 것은 장기 평균이고,
시장이 조용하다고 더 빌리라고 부추기면 이 서비스가 막으려던 일을 하게 된다.

계절작목은 비수확기에 거래가 끊긴다(딸기 최대 235일). 그 구간을 이어 붙이면 계절
전환이 폭락으로 잡히므로 수익률 계열을 끊는다.

**데이터 한계** — 가지는 KAMIS 중도매 시세가 없고(친환경 구분만 존재), 장미는
화훼라 농산물 가격 API에 수록되지 않아 교차검증이 불가능하다.

### 2) 영업레버리지(DOL) — 가격이 같아도 재배방식별 σ 가 갈리는 이유

도매시장에서 수경 딸기와 토경 딸기가 다른 값에 팔리지 않습니다. **가격 변동성은
품목의 성질이지 재배방식의 성질이 아닙니다.** 갈리는 곳은 비용 구조입니다.

```
소득 = 조수입 − 경영비
DOL = 1 + 고정비/소득
σ_소득 ≈ DOL × σ_조수입
```

수경은 양액설비·난방으로 고정비가 커서 DOL 이 높고, 같은 가격 충격에도 소득이 더
크게 흔들립니다. 필요한 입력은 작목별 조수입·경영비 두 숫자뿐이고 둘 다 소득조사
공표값이라, `--kosis` 실행 시 함께 잡히면 DOL 을 계산해 보여줍니다.

**실측 결과**: 딸기는 수경/관행의 DOL 이 사실상 같았지만(비율 0.99), **토마토는
수경이 1.33배**였습니다. 같은 가격을 받아도 수경 토마토의 소득이 33% 더 크게
흔들린다는 뜻이고, 이것이 σ 0.236 vs 0.178 의 차이로 이어집니다.

비율은 **반드시 겹치는 연도끼리** 계산합니다. 다른 해의 DOL 을 나누면 그 해의
작황·시세가 재배방식 차이로 둔갑합니다. 토마토는 구표(촉성, ~2022)와 수경(2023~)이
겹치지 않아, 같은 해에 존재하는 `시설토마토`(관행)를 대조군으로 씁니다
(`crops.json` 의 `ratio_base`).

이걸로 **분산분해**가 됩니다 (`stats/leverage.py`):

```
σ_개별² = σ_공통² + σ_고유²
```

현재 σ_공통은 실측, σ_고유는 `policy.json` 의 가정값 0.17 입니다.
**σ 에 남은 가정은 이것 하나**이고, 농가가 소득 이력을 넣으면 그것도 사라집니다.

### 3) 농가 소득이력 — 데이터 확보 없이 지금 동작

가장 정확한 σ 는 어떤 통계도 아니고 그 농가 자신의 이력입니다. 문제는 길이입니다.
관측 4개로 표본표준편차를 쓰면 추정치가 터집니다(실제로 σ=1.02 가 나오기도 합니다).

그래서 작목 σ 를 사전분포로 두고 개인 이력으로 갱신합니다 — 켤레사전분포
(scaled inverse-χ²) 하의 사후 평균입니다.

```
σ² = (ν₀·σ₀² + (n−1)·s²) / (ν₀ + n−1)      ν₀ = 8
```

관측이 적으면 작목 평균 쪽으로, 쌓일수록 개인 값 쪽으로 자동으로 끌립니다.
진단 화면의 "지난 농업소득 이력" 칸에 3개년 이상 넣으면 즉시 반영되고,
`sigma_source` 가 `MEASURED` 로 바뀌어 배지가 "내 이력 기반"으로 교체됩니다.
승계농은 부모 이력을 쓸 수 있어 이 경로가 특히 잘 맞습니다.

## σ 불확실성

σ_공통은 실측했지만 σ_고유(0.17)는 여전히 가정입니다. 그래서 결과를 점 하나로 내지
않고 적용 σ 주변의 밴드를 함께 반환합니다(`uncertainty` 필드). 격자는 작목별 σ 의
배수(×0.5~×1.5)라 **적용값이 항상 격자 안에 들어옵니다** — 고정 격자를 쓰면 장미
(σ=0.335)처럼 격자 밖으로 나가 버립니다.

`break_even_sigma` 는 "권장 한도가 목표 위험 안에 들어오는 최대 σ" 입니다.

### σ 를 실측으로 교체하기

`sigma_source` 가 `MEASURED` 로 바뀌면 화면의 "변동성 가정값" 배지는 자동으로 사라집니다.

**KAMIS 도매가격 직접 수집** — 인증키만 있으면 한 줄입니다.

```bash
export DATA_GO_KR_SERVICE_KEY='...'
python -m stats.calibrate --crop strawberry_hydro --kamis --years 10
```

인증키는 [공공데이터포털 데이터 15156057](https://www.data.go.kr/data/15156057/openapi.do)
에서 **활용신청**(자동승인·무료·개발계정 10,000건) 후 마이페이지의 일반 인증키(Decoding)를
씁니다. 코드나 저장소에 넣지 말고 환경변수로만 주입하세요.

**CSV 경로** — 이미 받아둔 시계열이 있을 때.

```bash
# 연간 소득 시계열 (가장 정확 — 환산 가정이 개입하지 않음)
python -m stats.calibrate --crop strawberry_hydro --csv income.csv \
    --column income --kind annual-income --source "농진청 소득조사 패널"

# 일별 가격 시계열
python -m stats.calibrate --crop strawberry_hydro --csv prices.csv \
    --column price --kind daily-price --seasonal 250 \
    --source "KAMIS 도매가격 2015-2025" --dry-run
```

#### KAMIS API 연동 상세

```
GET https://apis.data.go.kr/B552845/perDay/price
필수  serviceKey, returnType, pageNo, numOfRows(≤1000),
      cond[exmn_ymd::GTE], cond[exmn_ymd::LTE] (YYYYMMDD),
      cond[ctgry_cd::EQ], cond[item_cd::EQ]
선택  cond[se_cd::EQ], cond[vrty_cd::EQ], cond[grd_cd::EQ],
      cond[sgg_cd::EQ], cond[mrkt_cd::EQ], selectable
```

- 코드표 전체(구분·부류·품목 136·품종 332·등급 693·시군구 38·시장 216)는
  `data/kamis_codes.json` 에 있습니다. 작목별 매핑은 `crops.json` 의 `kamis` 필드입니다.
  예: 딸기 `200/226/00`, 토마토 `200/225/00`, 시금치 `200/213/00`.
- **오류 봉투가 두 종류입니다.** 서비스 오류는 명세대로 `response.header.resultCode`
  로 오지만, 인증·쿼터 실패는 게이트웨이가 HTTP 403 과 함께
  `OpenAPI_ServiceResponse.cmmMsgHeader` 라는 전혀 다른 모양으로 돌려줍니다.
  실제 호출로 확인해 둘 다 처리합니다.
- 같은 날 여러 도매시장 관측이 섞여 오므로 날짜별 평균으로 접은 뒤 로그수익률을
  냅니다. 접지 않으면 시장 구성 변화가 변동성으로 잡힙니다. 단위가 제각각이라
  `exmn_dd_cnvs_prc`(kg환산가격)를 우선 사용합니다.
- KAMIS 는 **품목 단위 가격**이라 수경/토경 재배방식을 구분하지 않습니다.
  딸기 두 작목은 같은 가격 계열을 공유합니다.

추정기는 로그수익률 표준편차 → √t 연율화 → 비모수 부트스트랩 95% 신뢰구간을
계산하고, 계절조정 옵션을 제공합니다.

**가격 σ 는 소득 σ 가 아닙니다.** 소득 = 수량 × 가격 − 비용이고 수량과 가격은 보통
음의 상관을 가집니다(풍년이면 값이 떨어짐). `price_to_income_sigma` 가 수량 탄력성
(기본 −0.5)으로 이 상쇄를 명시적으로 보정하며, 보정 계수 자체가 가정이므로 추정치에
함께 기록됩니다. 연간 소득 실측이 확보되면 이 환산 경로는 불필요해집니다.

## 알려진 한계

- **기본 σ 는 여전히 가정값이다.** KAMIS·KOSIS 수집 경로는 완성돼 있고 두 엔드포인트
  모두 실호출로 검증했지만, 인증키가 있어야 실제 수집이 돈다. 다만 소득이력 입력
  경로는 키 없이 지금 동작하므로, 이력이 있는 농가는 이미 개인화된 σ 를 받는다.
- **면적과 소득이 정비례한다고 본다.** 규모의 경제가 반영되어 있지 않다. 농가 단위
  원시자료가 있어야 곡선을 추정할 수 있다.
- **KOSIS 공표값은 전국 평균이라 σ 를 과소평가한다.** 하한으로 보고, 고유 성분은
  분산분해나 개인 이력으로 보완해야 한다.
- **재해확률 8% 도 가정값이다.** σ 와 달리 아직 밴드로 다루지 않는다.
- **면적→소득을 완전 비례로 본다.** 규모의 경제가 반영되어 있지 않다. 농진청
  원시자료(4,230농가)가 확보되면 분위회귀로 소득 분포 자체를 추정해 로그정규
  가정을 걷어낼 수 있다.
- 상환연기 처리 시 유예된 원리금을 뒤로 이월하지 않는다(연기 연차를 부족 집계에서
  제외하는 것까지만 모사). 실제 제도의 이월 원리금은 반영되어 있지 않다.
- 축산·과수 작목, 지자체 공고, 사용자 계정·저장은 범위 밖이다.
